# 前端设计说明

本文记录 MUXIN AI SCRM 前端的布局模型、视觉令牌和页面约定，便于后续扩展时保持一致性。

## 1. 设计目标

1. **信息架构清晰**：顶部按业务域切换，侧栏只呈现当前业务域，减少层级噪声。
2. **高密度可读**：面向日常运营，表格、筛选与操作区保持紧凑，同时保留足够留白。
3. **AI 可感知**：AI 能力作为独立业务域，与客户、订单等业务数据并列，而不是藏在设置页里。
4. **实现可维护**：视觉令牌集中在 `styles/theme.scss`，状态文案集中在 `navigation/constants.ts`。

## 2. 布局模型

```text
┌──────────────────────────────────────────────────────────┐
│ Logo   线索管理  客户管理  订单管理  系统设置  统计报表 ... │ 48px
├──────────┬───────────────────────────────────────────────┤
│ 侧栏      │ 系统公告                                       │ 36px
│ 当前模块  ├───────────────────────────────────────────────┤
│ 的子菜单  │ 页面标题                                       │
│          │ 筛选卡片                                       │
│          │ 操作栏 + 表格 + 分页                            │
└──────────┴───────────────────────────────────────────────┘
```

关键实现：

| 行为 | 实现 |
| --- | --- |
| 顶部按业务域分段，点击后切换整个侧栏 | `navSections` 同时描述顶部区块和侧栏条目 |
| 侧栏只显示当前业务域 | `findSectionByPath()` 根据路径匹配区块 |
| 筛选条件较多时自动换行 | `.scrm-filter-card` + `.scrm-filter-row` 使用 flex-wrap |
| 表格行高紧凑、表头浅灰、操作列靠右 | 统一覆盖 Element Plus 表格样式 |
| 状态用彩色标签表达 | `SCRM_ORDER_STATUSES` 等常量集中管理标签与颜色 |
| 公告条常驻内容区顶部 | 36px 公告条，4.5 秒轮播，可关闭 |
| 侧栏底部显示版本号 | 读取 `package.json` 版本或构建时注入 |

## 3. 视觉令牌

主色与基础色定义在 `frontend/src/styles/theme.scss`：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| 主色 | `#035cff` | 按钮、选中态、链接、图表柱 |
| 主色深阶 | `#0249cc` | hover / active |
| 主色浅底 | `#e8f0ff` | 浅色选中背景 |
| 侧栏背景 | `#001529` | 深色业务侧栏 |
| 侧栏 hover | `#0a2545` | 条目悬停 |
| 页面背景 | `#f5f6f9` | 内容区底色 |
| 卡片背景 | `#fff` | 筛选卡、表格面板 |
| 主文本 | `#222` / `#303133` | 标题与正文 |
| 次文本 | `#606266` | 表格内容、表单标签 |
| 弱文本 | `#909399` | 辅助信息 |
| 危险/提醒 | `#f56c6c` / `#f08a5d` | 必填星号、空状态提示 |
| 圆角 | `4px` | 按钮、输入框；标签为 `2px` |
| 卡片阴影 | `0 4px 12px rgb(0 0 0 / 12%)` | 筛选卡与内容面板 |

字体使用系统字体栈：

```css
font-family: "Microsoft YaHei", "微软雅黑", "Helvetica Neue", Arial, sans-serif;
font-size: 14px;
```

不引入 Web Font，避免额外请求和字体授权问题；不同操作系统下的字形会有细微差异。

## 4. 布局尺寸

| 区域 | 尺寸 / 行为 |
| --- | --- |
| 顶栏 | 固定，高 48px，白底，底部 1px 阴影 |
| Logo | 180px 宽，CSS 文本标识（「木心」色块 + `·` + `MUXIN`） |
| 顶部导航 | 七个业务域，图标 + 文案，选中项显示 2px 主色下划线 |
| 侧栏 | 固定，顶部从 48px 开始，宽 180px，深色背景 |
| 侧栏条目 | 高 48px，选中项主色填充 |
| 内容区 | `padding: 48px 20px 20px 200px`，让出顶栏和侧栏 |
| 公告条 | 高 36px，浅蓝底，轮播 + 圆点 + 关闭 |
| 响应式 | 1280px 以下缩小顶栏字号和内边距，侧栏 170px |

布局没有使用 `el-menu`，而是用原生按钮 + 自定义样式。顶部导航承担「业务域切换器」的职责，不是标准多级菜单；用 `el-menu` 反而要覆盖大量默认行为。

路由切换使用 140ms 透明度过渡。侧栏高亮规则：

```ts
if (route.path === path) return true;
if (path === "/crm/clues/create") return false; // 一次性入口不继承高亮
return route.path.startsWith(`${path}/`);
```

## 5. 页面模板

### 5.1 列表页

```text
页面标题
筛选卡片  关键词 / 状态 / 负责人 / 日期      查询 重置
面板头    标题                         新建 导出 批量操作
表格 + 分页
```

实现约定：

- 筛选项在 `query` 响应式对象中维护，点击「查询」重置页码后请求。
- 点击「重置」恢复默认值并立即查询。
- 删除、审核等破坏性操作使用 `ElMessageBox.confirm` 二次确认。
- 空数据不隐藏表头，保持页面结构稳定。
- 分页固定右对齐，页大小切换后回到第一页。

### 5.2 详情与编辑

- 轻量编辑使用 `el-dialog`，复杂详情使用 `el-drawer`。
- 客户详情抽屉按「基本信息 / 标签 / 跟进 / 商机 / 订单」分区。
- 表单校验集中在组件内，提交失败保留用户输入。
- 金额输入使用 `el-input-number`，提交前转为数值。

### 5.3 状态标签

状态与颜色集中在 `frontend/src/navigation/constants.ts`：

| 状态 | 文案 | 标签类型 |
| --- | --- | --- |
| 订单 1 | 待审核 | warning |
| 订单 2 | 已确认 | primary |
| 订单 3 | 已完成 | success |
| 订单 4 | 已取消 | info |
| 客户 1 | 潜在客户 | info |
| 客户 2 | 跟进中 | primary |
| 客户 3 | 已成交 | success |
| 客户 4 | 已流失 | danger |

新增状态时只改这一处，避免页面里散落魔法数字。

## 6. 报表页

### 6.1 员工业绩

```text
日期范围 + 部门 + 员工 + 查询/重置/导出
5 张统计卡
成交金额 Top 8 柱状图
员工明细表
```

- 默认区间为最近 7 天（含今天）。
- 日期、部门、员工变化时重新请求或重绘图表。
- 部门与员工筛选是前端过滤：后端只按日期返回全部员工，前端再按 `deptName`、`userName` 过滤。
- 统计卡、图表与导出的 CSV 使用同一份过滤结果。
- 图表使用 ECharts 按需引入，窗口 resize 时调用 `chart.resize()`。

统计卡中的「新增客户」实际是员工名下客户总数，卡片脚注写明「名下客户总数」，真实统计口径以接口文档为准。

### 6.2 员工绩效

两个子标签：

- **签收绩效**：客户数、跟进数、订单数、金额，按固定权重合成评分；
- **线索转化绩效**：订单数、成交率、客单价等派生指标。

页面复用员工业绩接口，派生公式集中在页面内，便于替换为真实规则。

### 6.3 CSV 导出

- 纯前端生成，使用 `Blob` + `URL.createObjectURL`。
- 以 UTF-8 BOM (`\uFEFF`) 开头，保证 Excel 打开中文不乱码。
- 字段统一加双引号，内部双引号转义为 `""`。
- 文件名包含日期区间或页面名称。

## 7. AI 页面

### 7.1 工作台

左侧会话列表，右侧分析结果：

- 摘要、需求、异议、预算、决策人、双方承诺、下一步动作、情绪与意向；
- 标签建议逐条展示证据，可采纳或忽略；
- 跟进建议确认后写入跟进记录；
- 模型通道与耗时在结果区标注，便于判断是否走了 Mock。

### 7.2 智能质检

- 顶部概览卡：任务数、命中数、待复核数、违规率；
- 规则维护使用对话框，`instruction` 为必填；
- 任务创建后轮询或手动刷新执行状态；
- 结果列表展示规则、严重级别、证据原文与复核状态；
- 复核操作只有「确认违规 / 误报」两种，避免模糊状态。

### 7.3 设置

- 模型配置：provider、baseUrl、model、apiKey、temperature、maxTokens；
- Key 保存后只显示掩码，留空表示不修改；
- 连通性测试结果区分真实模型与 Mock 回退；
- Prompt 模板展示版本号，保存即递增；
- 用量概览按功能聚合调用次数与 Token。

## 8. 业务语言映射

界面概念与数据模型的对应关系：

| 界面概念 | 数据 | 规则 |
| --- | --- | --- |
| 线索 | `biz_customer` | `status = 1` |
| 客户 | `biz_customer` | `status IN (2, 3)` |
| 转为客户 | 更新状态 | `1 -> 2` |
| 订单 | `biz_contract` | 合同即订单 |
| 待审核 | `biz_contract.status` | `1` |
| 审核通过 | 更新状态 | `1 -> 2` |
| 订单完成 | 更新状态 | `2 -> 3` |
| 客户编码 | `biz_customer.id` | 前端补零为 `C000001` |

映射层只存在于前端筛选参数和少量后端查询中，数据库仍使用通用业务表名（如 `biz_contract`），便于复用既有模块。

## 9. 占位页策略

导航中包含尚未实现的入口（加粉、打单发货、云仓、部分报表等）。处理方式：

- 保留导航条目和路由，保证信息架构完整；
- 统一渲染 `PlaceholderPage`，提示「当前账号暂无查看权限，或该模块尚未配置」；
- 不伪造按钮、不假装有数据、不拦截真实操作。

宁可明确「尚未实现」，也不做看起来能用、实际无行为的假交互。云店管理页展示平台卡片与授权说明，但没有真实授权能力。

## 10. 可访问性与性能

已做：

- 可点击元素使用 `<button>` 或 Element Plus 组件，保留键盘焦点；
- 图标按钮配 `el-tooltip` 文案；
- 颜色不是唯一信息载体，状态同时有文字；
- 路由懒加载，报表页按需初始化 ECharts；
- 图表在组件卸载时销毁，定时器在 `onBeforeUnmount` 清理。

尚未做：

- 完整的键盘导航与屏幕阅读器测试；
- 移动端适配，1280px 以下仅做轻度收缩；
- 暗色主题；
- 国际化，文案全部为简体中文。

## 11. 后续改进

1. 用 CSS 变量收敛颜色和间距，支持主题切换。
2. 抽出 `FilterCard`、`DataPanel`、`StatusTag` 等通用组件，减少页面重复。
3. 把部门/员工筛选移到后端，避免大数据量下的前端过滤。
4. 为表格增加列设置、密度切换和导出范围选择。
5. 补充空状态与错误状态页，继续使用原创图形。
6. 为 AI 结果区增加骨架屏、失败重试与引用证据高亮。
